# 01 micrograd

(記入: AI との対話をもとに AI が整理。実験値は 2026-08-14 に実測)

## 一言でいうと

スカラー版の自動微分エンジン(Value)をゼロから作り、その上に MLP を組んで、
4サンプルのおもちゃデータで学習ループを回した。PyTorch が裏でやっていることの最小再現。

## コードの説明(自分の言葉で)

**value.py = 部品 + エンジン**
- 部品(`__add__` `__mul__` `__pow__` `tanh`): 各演算は「forward 計算」
  「グラフ記録(_prev に親を覚える)」「勾配の配り方(_backward)」をワンセットで持つ
- _backward の中身は常に「局所勾配 × out.grad を入力に**足す**」= 連鎖律。
  `+=` なのは同じ変数が複数経路で使われたとき寄与を合算するため(`=` だと上書きで壊れる)
- エンジン(`backward()`): トポロジカルソート → 出力の grad=1 → 逆順に _backward 実行。
  逆順が必須なのは、各ノードの grad が確定してからでないと配る量が決まらないから
- 引き算・割り算は add/mul/pow の合成なので専用の微分コード不要

**nn.py = 配管(微分コードゼロ行)**
- 唯一の計算は `Neuron.__call__` の `tanh(w・x + b)` 1行。
  Layer は「同じ入力を n_out 人の審査員に配って採点表を作る」、
  MLP は「隣り合うサイズのペアで Layer を作って直列につなぐ」だけの事務作業
- w はランダム初期化(全員同じだと1ニューロンに潰れる=対称性を破る係)、
  b は 0 初期化(中立なしきい値。大きい値は tanh 飽和のリスク)→ 詳細は下の Q&A
- 賢さは構造でなく、学習後の w と b の値に宿る

**train_demo.py = 5拍子 × 100周**
1. forward(グラフが組まれる)
2. loss(4サンプルの二乗誤差をスカラー1個に集約 = backward の出発点)
3. zero_grad(+= の裏返し。前周の勾配を消す)
4. backward(41パラメータ全部に「増やしたら loss がどれだけ増えるか」が届く)
5. update(`p.data -= lr * p.grad`。data 直接更新なのでグラフに載らない)
- グラフは毎周使い捨て。生き残るのは更新された data だけ
- loss 5.28 → 0.011。前半急落・後半逓減が典型的なカーブ

**test_vs_torch.py**: 同じ式を PyTorch でも組み、forward と勾配が一致することを確認済み

## 改造実験(1変数ずつ)

seed=42 固定、他は baseline(lr=0.05, 100 step, loss: s0 5.279 → s99 0.011)と同一。

| 変えたもの | 変更前→後 | 何が起きたか | なぜそうなる? |
|---|---|---|---|
| lr | 0.05 → 1.0 | s10 で loss=8.0 に張り付き学習停止。preds 全4件が +1.0000 に飽和(2件は真逆)。勾配合計 8e-6 | 歩幅が大きすぎて tanh の飽和領域に飛び込む。微分 1-tanh² ≈ 0 で勾配が消え、戻る手段がなくなる。loss=8 は「2件が最大限に間違う」(2²+2²) |
| tanh を外す | tanh → 恒等関数 | s10 までに loss が nan(発散) | 出力を ±1 に抑える箱がなくなり誤差も勾配も無制限に増大。lr=0.05 では更新が過大になり発散 → inf-inf で nan |
| zero_grad を消す | あり → なし | 一見**予想外に高速収束**(s10: 0.018 vs 0.397)。だが追検証で max\|w\| が 34→105→351(step 100→300→1000)と無限成長しており**実は壊れていた**。loss=0 のまま重みだけ等速ドリフト | 蓄積勾配がモメンタム的に働き序盤は加速。loss≈0 後も「過去の勾配の総和」で毎步同じ方向へ動き続けるが、tanh 飽和が出力を ±1 に固定するので loss に現れない(silent bug)。定番バグ「zero_grad 忘れ」はおもちゃ問題では隠れることがある |
| b の初期値 | 0.0 → uniform(-1,1) | ほぼ変わらない(s99: 0.0099 vs 0.0111)。予想どおり | 対称性は w が破っており、小さい b は飽和も起こさない。初期値の差は学習が吸収する |
| b の初期値 | 0.0 → 全部 5.0 | loss=8.0 で完全凍結。preds 全4件 +1.0000、勾配合計 1e-4。予想どおり | 全ニューロンが最初から飽和側に置かれ、勾配がほぼ流れず学習が始まらない |

**学び**:
- 停滞の原因は2種類見えた: 「飽和で勾配が消える」(lr=1.0, b=5.0)と
  「更新が大きすぎて発散」(tanh なし)
- **loss だけ見ても壊れに気づけない**(zero_grad なしは loss 最良なのに
  重みが無限成長していた)。重み・勾配のノルムも観察対象に入れる。
  「良すぎる結果が出たら中身を覗く」(リーク検知と同じ嗅覚)
- 意図的な勾配蓄積は gradient accumulation という正規テクニック
  (N 回溜めて1回更新→ゼロ戻し)。制御すれば道具、忘れればバグ

## 詰まったところ・分かってなかったこと

### Q: なぜ w はランダム初期化で、b は 0 初期化なのか(2026-08-14)

- 対称性を破る仕事は w のランダム化だけで足りる。全ニューロンを同じ値で
  初期化すると全員が同じ出力・同じ勾配・同じ更新になり、実質1ニューロンに
  潰れる。w がランダムなら b は全員 0 スタートでも、各 b に流れる勾配が
  ニューロンごとに違うので問題ない
- b の役割は活性化のしきい値調整。学習前は「どちらにずらすべきか」の根拠が
  ないので、ずらさない = 0 が中立なデフォルト
- 大きな bias を最初に与えると tanh が飽和(±2 あたりから平ら)し、
  微分 1 - tanh² が ≈0 になって勾配が流れず学習が止まるリスクがある
- **b は「ランダムになる」のではなく「学習で分化する」**。
  w のランダム性は最初の一押し(全員同じ、を崩す)だけで、その後の b の値は
  勾配降下がデータに合わせて決める。同じデータ・同じシードなら毎回同じ b に
  収束する(デタラメではなく最適化の結果)。
  一言: b は w のランダム性をきっかけに、データによって別々の値に育てられる
- 補足: 0 でなければ壊れるわけではない。PyTorch の nn.Linear は bias も
  小さい一様乱数で初期化する。「w はランダム必須・b は 0 が無難な慣習」
